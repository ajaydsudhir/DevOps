# Day 4: Script Execution Permissions

## Task
In a bid to automate backup processes, the `xFusionCorp Industries` sysadmin team has developed a new bash script named `xfusioncorp.sh`. While the script has been distributed to all necessary servers, it lacks executable permissions on `App Server 2` within the Stratos Datacenter.

Your task is to grant executable permissions to the `/tmp/xfusioncorp.sh` script on `App Server 2`. Additionally, ensure that all users have the capability to execute it.

## Solution
1. Connect to `App Server 2` using SSH:
    ```bash
    ssh steve@stapp02    # Password: Am3ric@
    ```
2. Grant executable permission to the script:
    ```bash
    sudo chmod +x /tmp/xfusioncorp.sh
    ```
    Ensure all users can execute it by using:
    ```bash
    sudo chmod a+x /tmp/xfusioncorp.sh
    ```
    **Alternatively**, set precise permissions:
    ```bash
    sudo chmod 755 /tmp/xfusioncorp.sh
    ```
3. Verify the permissions of the script:
    ```bash
    ls -l /tmp/xfusioncorp.sh
    ```
    The output should indicate that the script has executable permissions for the owner, group, and others (e.g., `-rwxr-xr-x`).

## Notes
- The `chmod` command is used to change the permissions of a file. The `+x` option adds executable permissions, while `a+x` ensures that all users (owner, group, and others) can execute the file.
