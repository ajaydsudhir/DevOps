# Day 12: Linux Network Services

## Task
Our monitoring tool has reported an issue in `Stratos Datacenter`. One of our app servers has an issue, as its Apache service is not reachable on port `8082` (which is the Apache port). The service itself could be down, the firewall could be at fault, or something else could be causing the issue.

Use tools like `telnet`, `netstat`, etc. to find and fix the issue. Also make sure Apache is reachable from the jump host without compromising any security settings.
Once fixed, you can test the same using command `curl http://stapp01:8082` command from jump host.

## Solution
1. SSH into `App Server 1`:
    ```bash
    ssh tony@stapp01    # Password: Ir0nM@n
    ```
2. Identify what is using port 8082:
    ```bash
    sudo ss -tulpn | grep 8082
    ```
3. Stop the conflicting service:
    ```bash
    sudo systemctl stop sendmail
    ```
4. Verify port 8082 is free:
    ```bash
    sudo ss -tulpn | grep 8082
    ```
5. Start Apache:
    ```bash
    sudo systemctl start httpd
    ```
6. Enable Apache:
    ```bash
    sudo systemctl enable httpd
    ```
7. Verify Apache is listening on 8082:
    ```bash
    sudo ss -tulpn | grep 8082
    ```
8. Allow inbound access to port 8082:
    ```bash
    sudo iptables -I INPUT 5 -p tcp --dport 8082 -j ACCEPT
    ```
9. Verify firewall rule:
    ```bash
    sudo iptables -L INPUT -n --line-numbers
    ```
10. Test on `App Server 1`:
    ```bash
    curl http://localhost:8082
    ```
11. From `jump host`:
    ```bash
    curl http://stapp01:8082
    ```

## Notes
- The issue was caused by `sendmail` service which was using port `8082`. Stopping `sendmail` and starting `httpd` resolved the issue.
- The firewall was configured to allow traffic on port `8082` to ensure accessibility from the jump host.
