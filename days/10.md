# Day 10: Linux Bash Scripts

## Task
The production support team of `xFusionCorp Industries` is working on developing some bash scripts to automate different day to day tasks. One is to create a bash script for archiving website content files. They have a static website running on `App Server 2` in `Stratos Datacenter`, and they need to create a bash script named `news_archive.sh` which should accomplish the following tasks. (Also remember to place the script under the `/scripts` directory on `App Server 2`).

a. Create a zip archive named `xfusioncorp_news.zip` of `/var/www/html/news` directory.
b. Save the archive in the `/archives/` directory on the `App Server 2`. This is a temporary storage, as archives from this location will be cleaned on a weekly basis. Therefore, the archive should also be copied to the `Nautilus Storage Server` so it can be retrieved later for validation purposes.
c. Copy the created archive to the `Nautilus Storage Server` server in the `/archives/` location.
d. Please make sure script won't ask for password while copying the archive file. Additionally, the respective server user (for example, `tony` in case of `App Server 1`) must be able to run it.
e. Do not use sudo inside the script.

Note:
The zip package must be installed on given App Server before executing the script. This package is essential for creating the zip archive of the website files. Install it manually outside the script.

## Solution
1. SSH into `App Server 2`:
    ```bash
    ssh steve@stapp02   # Password: Am3ric@
    ```
2. At `root`, install the `zip` package:
    ```bash
    yum install -y zip
    ```
3. Create the directories if they don't exist:
    ```bash
    mkdir -p /archives
    mkdir -p /scripts
    ```
4. At `steve` home directory, generate the SSH key pair for passwordless authentication to `Nautilus Storage Server`:
    ```bash
    su - steve
    ssh-keygen  # Press Enter to accept default file location and no passphrase
    ssh-copy-id natasha@ststor01  # Password: Bl@kW
    ```
5. Verify passwordless SSH access to `Nautilus Storage Server`:
    ```bash
    ssh natasha@ststor01  # Should not ask for password
    exit  # Exit back to stapp02
    ```
6. At `root`, create the `news_archive.sh` script in `/scripts` directory using the `vi /scripts/news_archive.sh` command and add the following content:
    ```
    #!/bin/bash
    zip -r /archives/xfusioncorp_news.zip /var/www/html/news
    scp /archives/xfusioncorp_news.zip natasha@ststor01:/archives/
    ```
7. Make the script executable:
    ```bash
    chmod 755 /scripts/news_archive.sh
    ```
8. Set the ownership of the script to `steve`:
    ```bash
    chown steve:steve /scripts/news_archive.sh
    ```
9. Run the script as `steve` to create the archive and copy it to the storage server:
    ```bash
    su - steve
    /scripts/news_archive.sh
    ```
10. Verify that the archive is created in `/archives` on `App Server 2`:
    ```bash
    ls -l /archives/xfusioncorp_news.zip
    ```
11. Verify that the archive is copied to `Nautilus Storage Server`:
    ```bash
    ssh natasha@ststor01    # Password: Bl@kW
    ls -l /archives/xfusioncorp_news.zip
    exit
    ```

## Notes
- https://man.openbsd.org/scp
- https://linux.die.net/man/1/zip
- https://www.gnu.org/software/coreutils/manual/html_node/chown-invocation.html
- The `zip` command is used to create a zip archive of the specified directory. The `-r` option is used to include all files and subdirectories recursively.
- The `scp` command is used to securely copy files between hosts on a network. In this case, it is used to copy the created zip archive from `App Server 2` to the `Nautilus Storage Server`. The syntax is `scp source_file user@destination_host:destination_path`.
- The `chmod 755` command sets the permissions of the script to be readable and executable by everyone, but only writable by the owner. This allows the script to be run by any user while ensuring that only the owner can modify it.
- The `chown` command is used to change the ownership of the script to the user `steve`, ensuring that he has the necessary permissions to execute it.
- The script should be run as the `steve` user to ensure that it has the appropriate permissions to access the website files and create the archive. Running it as `root` leads to permission issues when accessing user files or copying to the storage server.
