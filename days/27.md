# Day 27: Git Revert Some Changes

## Task
The Nautilus application development team was working on a git repository `/usr/src/kodekloudrepos/beta` present on `Storage server` in `Stratos DC`. However, they reported an issue with the recent commits being pushed to this repo. They have asked the DevOps team to revert repo HEAD to last commit. Below are more details about the task:
1. In `/usr/src/kodekloudrepos/beta` git repository, revert the latest commit `( HEAD )` to the previous commit (JFYI the previous commit hash should be with `initial commit` message ).
2. Use `revert beta` message (please use all small letters for commit message) for the new revert commit.

## Solution
1. SSH into the `Storage Server` using the provided credentials.
   ```bash
   ssh natasha@ststor01    # Password: Bl@kW
   ```
2. Navigate to the git repository `/usr/src/kodekloudrepos/beta`.
   ```bash
   cd /usr/src/kodekloudrepos/beta
   ```
3. Check the git log to identify the latest commit and the previous commit.
   ```bash
   sudo git log
   ```
4. Revert the latest commit to the previous commit using the `git revert` command and when prompted, use the commit message `revert beta`.
   ```bash
   sudo git revert HEAD
   ```

## Notes
- `git revert` is used to create a new commit that undoes the changes made by the specified commit. It does not delete any commits from the history, making it a safe way to undo changes.
- Git revert is different from `git reset` as it preserves the commit history and is generally preferred for collaborative workflows.
- https://git-scm.com/docs/git-revert.html
