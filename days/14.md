# Day 14: Linux Process Troubleshooting

## Task
The production support team of xFusionCorp Industries has deployed some of the latest monitoring tools to keep an eye on every service, application, etc. running on the systems. One of the monitoring systems reported about Apache service unavailability on one of the app servers in `Stratos DC`.
Identify the faulty app host and fix the issue. Make sure Apache service is up and running on all app hosts. They might not have hosted any code yet on these servers, so you don't need to worry if Apache isn't serving any pages. Just make sure the service is up and running. Also, make sure Apache is running on port `3000` on all app servers.

## Solution
1. Connect to each application server using the provided credentials on three separate terminals.
    ```bash
    ssh tony@stapp01       # Terminal 1 - Password: Ir0nM@n
    ssh steve@stapp02      # Terminal 2 - Password: Am3ric@
    ssh banner@stapp03     # Terminal 3 - Password: BigGr33n
    ```
2. Check the status of the Apache service on each server to identify the faulty one.
    ```bash
    systemctl status httpd -l
    ```
    OUTPUT:
    - On `stapp02` and `stapp03`, the service is active and running.
    - On `stapp01`, the service is inactive (dead).

3. The error message indicates that the Apache service is trying to bind to port `3000`, but it is already in use by another process. To identify which process is using port `3000`, run the following command:
    ```bash
    sudo lsof -i :3000
    ```
    OUTPUT:
    ```
    COMMAND    PID USER   FD   TYPE     DEVICE SIZE/OFF NODE NAME
    sendmail 19575 root    4u  IPv4 2837184754      0t0  TCP localhost:hbci (LISTEN)
    ```
4. The `sendmail` service is using port `3000`, which is causing the conflict with Apache. Stop the `sendmail` service and disable it:
    ```bash
    sudo systemctl stop sendmail
    sudo systemctl disable sendmail
    ```
5. After stopping the `sendmail` service, start the Apache service againvand verify that it is now active and running on `stapp01`:
    ```bash
    sudo systemctl start httpd
    systemctl status httpd -l
    ```

## Notes
- It's important to ensure that critical services like Apache are not configured to use ports that may be occupied by other services, especially in a production environment.
